Visão Geral do Ciclo de Vida do Software

1

Backpressure Determinístico

Nenhum commit é publicado sem que a suíte completa rode localmente no Mac através do hook .githooks/pre-push. O script scripts/check.sh valida ESLint, TypeScript, testes de governança, banco efêmero em Docker e build Next.js.

2

Soberania Humana & SemVer

O deploy de produção só existe atrelado a uma tag SemVer formal (v1.0.X) emitida exclusivamente após o PR de dev para main ser aprovado por Jeann Lucas. Deploys diretos por push de branch são estritamente bloqueados.

3

Tailscale & Wrapper SSH Restrito

A VPS não expõe SSH público. O runner do GitHub se conecta via Tailscale Mesh privada. A chave SSH exclusiva está travada em authorized_keys com command="/usr/local/bin/propatch-deploy", rejeitando comandos arbitrários e aceitando apenas uma tag SemVer válida.

4

Pré-Voo Fail-Closed

Antes de derrubar o app em produção ou alterar qualquer tabela, a VPS compila a imagem nova e testa o carregamento das dependências críticas (postgres e drizzle-orm). Se houver erro de empacotamento, o deploy aborta com zero downtime.

5

Snapshot & Rollback Seguro

Antes de qualquer migração, os escritores são pausados e um snapshot integral com checksum SHA256 é registrado em /srv/propatchbr/backups/db/. Em caso de falha de inicialização, o script reativa a versão anterior imediatamente.

6

Preservação de Volumes

O banco de dados (propatchbr_postgres_data) e o armazenamento de binários ISO (propatchbr_patches_data) utilizam volumes persistentes desacoplados do ciclo de vida das imagens, garantindo que deploys e reboots nunca apaguem dados de clientes.

Guia Rápido do Desenvolvedor: Como Trabalhar no Dia a Dia

Etapa Comando Canônico O que acontece por trás?
1. Iniciar Tarefa git checkout dev && git pull && git checkout -b feature/minha-feature Sincroniza a branch base e isola a alteração em branch dedicada.
2. Desenvolver & Testar npm run dev (ou ./scripts/check.sh --quick) Validações rápidas de linter e tipos durante o desenvolvimento.
3. Integrar na dev git checkout dev && git merge --no-ff feature/minha-feature Integra o código na dev local para validação integrada pré-push.
4. Publicar na dev git push origin dev Dispara a barreira do pre-push hook que roda ./scripts/check.sh 100% verde.
5. Solicitar Promoção gh pr create --base main --head dev Abre Pull Request no GitHub. O CI roda testes de compilação.
6. Aprovação & Merge gh pr merge <PR> --merge Cria merge commit na main com rastreabilidade auditável.
7. Disparar Deploy VPS git tag -a v1.0.X <COMMIT> -m "Release v1.0.X" && git push origin v1.0.X Dispara o pipeline automatizado: Tailscale ➔ SSH Restrito ➔ Deploy VPS.
